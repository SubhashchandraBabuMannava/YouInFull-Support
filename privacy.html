Privacy, in plain view.

Keep your journal local. Review the specific information an export, reference request or earlier result check can move.

What this notice covers

This notice covers the free local YouInFull release candidate and this support website, as described in November 2026. The app is still in preparation for App Store release. Local use requires no YouInFull account or subscription.

The maintainer can be contacted through project support on GitHub. That route is public and requires a GitHub account; use it only for non-sensitive questions. Use private security reporting for a security concern.

Your journal stays in a protected local store

YouInFull stores the entries, meals, routines, plans, notes and original records you choose to keep. Existing saved source records and their provenance remain available. Choosing a file or image can retain its original bytes with unfinished input before you save a completed entry; closing an editor is different from discarding that input.

The canonical store is on this device. New cloud synchronization, shared-care enrollment and clinical-service connections are not offered in this release. The working store and retained documents use complete file protection on iOS and are excluded from device backup.

Recovery is explicit: create an encrypted archive, keep it outside this device and keep its key separately. Files or the share sheet can hand the encrypted file to a location or provider you select; that provider handles the copy under its own terms. No YouInFull server receives a newly created local archive or its key. The destination person and current state are checked before restoration.

Local search can include a limited text projection in Apple’s protected on-device Core Spotlight index. This index is separate from the app’s database. Source changes and deletion are handled by the existing indexing and evidence-update owners.

Optional assistance

Manual entries and deterministic history work without AI. Available Apple on-device language tasks use the selected question and source context. Generated material stays separate from a source record or an accepted plan and requires your review.

New requests do not use NVIDIA or another non-Apple model service. Private Cloud Compute is not enabled in this candidate. An unavailable task keeps its source and unfinished work; it does not silently send the information elsewhere.

Earlier server-assisted requests retain their original operation identifiers, input commitments, usage, status and encrypted results. An explicit original-result check can contact the existing service with those identifiers. It does not send a new inference request or erase information that was already transmitted. General operational logs exclude the question, source text and generated output.

Where voice input is available, Apple’s on-device speech processing uses microphone permission and leaves editable text. Apple model or speech assets may need to be downloaded. On-device processing does not mean the device never uses a network.

Free use and earlier purchase records

The selected local release has no Plus purchase, subscription or trial path. Its journal, meals, chosen routines, private records, export and encrypted recovery need no payment or YouInFull account.

Earlier financial and service records are preserved. Apple handles any earlier Apple-billed purchase; deleting local health content does not cancel an Apple subscription or erase Apple’s purchase history. Restoring health records does not recover a purchase, an archive key or another person’s access.

The retained financial implementation has separate membership identifiers, hashed account and transaction identifiers, verified product and entitlement metadata. The free composition does not initiate that paid lifecycle. YouInFull does not receive a payment-card number or Apple Account password.

Public references and network requests

Manual food entries and the available food index work locally. Selecting a public food whose details are not cached can download its signed reference file from GitHub Releases and its asset hosts. That request identifies the public file; it does not include raw food-search words, meal content, photos, an account token or the app’s device identity. GitHub receives connection information needed to serve the file under its privacy practices.

Older saved reference readers can retain an explicit National Library of Medicine lookup. If you choose that lookup, the entered term or code goes to the selected MedlinePlus Connect, DailyMed or PubMed/NCBI service, along with network request information. Do not enter your name, personal history or record identifiers into a public-reference lookup. NLM describes its request information and search-term handling in its web policies.

Opening an original source website is a separate action governed by that site’s own practices. An ephemeral app network session does not control what a receiving service retains. An unavailable food reference never blocks a manual entry or supplies invented nutrition.

Export and previously shared originals

There is no new circle, invitation, shared-care, standing workout-sharing or nearby-transfer acquisition in the free release. Existing locally saved shared material, keys and original operation records are preserved. Local readers do not create a replacement account or adopt someone else’s records.

Earlier connection services may retain encrypted content and operational identifiers, public keys, membership and delivery history. Retiring new sharing does not erase those originals or retrieve a recipient’s copy. An original result or deletion check remains bound to its original operation; an unknown outcome must be reconciled before any retry.

Review the exact content before an export. Files and recipients outside YouInFull can keep their copies. Local deletion does not erase an exported file. An archive refuses missing required originals instead of silently dropping them or fetching private content from the relay.

Previously saved circle safety controls and private-report preparation remain distinct from sending a report. The private GitHub reporting form receives only what you choose to submit there. No report is submitted automatically.

Reliability and notifications

No production reliability-event transport is configured in the app, and the free composition does not enable a sharing switch. Firebase automatic initialization, default data collection and circle push are disabled in this candidate.

Local reminders use this device’s notification settings. A notification does not save a note, complete a routine or upload the journal. Reminder activation and device permissions must be reviewed after restoration.

This website and support

This is a static GitHub Pages site. Its code sets no cookies, uses no analytics service, sends no analytics or help-search requests and stores no search history. Help search filters topics already in the page without putting the query in a URL.

GitHub receives requests needed to serve the site and may process connection and usage information under the GitHub General Privacy Statement. Local help-search behavior does not control GitHub’s hosting records.

Support issues you choose to post are public. Closed discussions remain visible unless removed. Do not post health records, identifying screenshots or credentials. Private security reports are limited to the security-reporting route and authorized repository participants; this is not a clinical support channel.

To request removal from a support post, identify the post without repeating sensitive content. GitHub separately controls its platform records. Support does not give the maintainer access to your local journal or recovery key.

Your choices and retention

You choose what to import, save, edit and delete. Unfinished input stays with its selected person until it is saved or explicitly discarded. A changed or removed source can invalidate a dependent interpretation without silently replacing your authored words.

Changing access to an external source is different from deleting a saved local copy or deleting that source’s original. Deleting the app can lose local work. Recovery needs an independently kept archive and its key; support cannot retrieve a missing store or reset that key.
